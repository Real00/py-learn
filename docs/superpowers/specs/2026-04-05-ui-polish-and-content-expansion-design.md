# Python 入门课程界面细节优化与第一章内容扩充设计

## 1. 背景

当前主分支上的课程界面已经完成了一轮结构升级，但仍然存在几类明显影响观感和可用性的问题：

- 全局配色偏亮蓝，部分区域出现“蓝底黑字”或高饱和蓝底搭配深色文字的观感，整体不够专业。
- 进度页中的状态标签在窄空间下会被挤压，`进行中` 会出现不自然的竖向断裂。
- 首页“学习路线”卡片目前只是展示信息，不能像真正的课程入口一样承担导航功能。
- 第一章《Python 到底是什么》虽然已经比最初版本更完整，但对“Python 可以用来做什么”的说明仍然偏薄，无法有效帮助零基础用户建立学习动机。

本次工作聚焦于在不重做信息架构的前提下，完成一轮更专业的视觉收敛、交互修正和内容补强。

## 2. 目标

- 将全局视觉收敛到更专业、更克制的“冷静学院风”。
- 修正进度页状态标签挤压问题，保证小屏和窄布局下的稳定性。
- 让首页“学习路线”卡片承担真实导航功能。
- 保持当前章节解锁规则：已解锁章节可进入，未解锁章节不可进入。
- 扩充第一章中“Python 可以做什么”的内容密度和解释深度。

## 3. 非目标

- 不重做整站信息架构。
- 不修改课程章节顺序。
- 不引入新的后端接口。
- 不新增账户、同步、收藏等平台能力。
- 不对全部章节再做一次大规模重写，本轮内容改动聚焦第一章。

## 4. 用户确认的关键决策

### 4.1 视觉方向

采用 `A. 冷静学院风`：

- 低饱和灰蓝背景
- 深海军蓝正文
- 克制的浅色卡片与边框
- 高亮色只用于 CTA、链接、焦点和进度强调

目标是解决当前偏亮蓝带来的不专业感，同时保留学习产品应有的清晰和轻盈。

### 4.2 首页学习路线卡片交互

- 已解锁章节：整卡可点击，直接进入对应章节。
- 未解锁章节：整卡不可点击，不允许跳过解锁顺序进入。

这一定义必须同时反映在视觉状态和交互行为上，避免用户误判。

## 5. 设计方案

### 5.1 全局视觉系统调整

#### 5.1.1 颜色策略

当前问题不是“用了蓝色”，而是高饱和蓝色覆盖面积过大，导致界面看起来轻浮，且文本对比关系不够稳定。本轮调整采用“浅灰蓝背景 + 深色正文 + 中等强调蓝”的结构：

- `background`：更浅、更偏灰的冷色背景，用于页面底层和大面积留白区域。
- `foreground`：深海军蓝，用于标题和正文，提升稳定性和阅读信任感。
- `card`：近白色卡面，保留轻微透明感，但不再过度依赖明艳底色制造层级。
- `primary`：降低面积、提高用途纯度，只服务于按钮、链接、焦点、激活态和进度强化。
- `secondary / muted`：作为浅层信息底和辅助标签底色，避免和主按钮争抢注意力。

#### 5.1.2 卡片与层级

页面层级将优先通过以下方式建立，而不是靠大面积纯色：

- 边框明度差
- 阴影的软硬和透明度
- 间距与块级留白
- 标题、说明文字和状态区域之间的对比

结果应该是：

- 首页、课程页、进度页都保持同一种“克制、可信”的课程产品气质
- 卡片清晰但不“糊”
- 强调操作时有明确反馈，但不刺眼

### 5.2 状态标签与小屏稳定性

状态标签问题本质上不是单个文案长度，而是容器布局没有给标签保留足够的独立空间。

本轮会从两个层面修正：

#### 5.2.1 Badge 组件本身

- 标签改成强制单行展示
- 禁止被压缩到竖排
- 保持圆角胶囊形态
- 成功、进行中、待解锁三类状态继续保留明显但克制的色彩区分

#### 5.2.2 页面布局容器

进度页章节头部从“自由挤压”的左右布局，改成“正文区 + 状态区”的稳定结构：

- 状态区不参与正文压缩
- 标题和摘要在空间不足时优先换行
- 标签保持一行可读

这样可以同时解决“进行中”被挤压和标题摘要互相抢空间的问题。

### 5.3 首页学习路线改造

首页“学习路线”区域从静态信息列表升级为轻量导航入口，但仍然与完整课程页保持层级区分。

#### 5.3.1 卡片信息结构

每张卡片展示：

- 章节序号
- 标题
- 摘要
- 当前状态

首页版本不额外堆叠太多元信息，避免与课程总览页重复过多。

#### 5.3.2 可点击规则

- 已解锁卡片使用整卡点击
- 未解锁卡片保持静态展示，不提供章节跳转
- 已解锁卡片提供明确 hover、focus 和指针反馈
- 未解锁卡片通过更弱的文字、边框和背景状态体现“可见但不可进”

#### 5.3.3 视觉反馈

已解锁卡片应具备：

- 轻微上浮或阴影增强
- 边框强调
- 指针样式

未解锁卡片应具备：

- 更低对比度
- 无指针
- 明确的状态标签

### 5.4 进度页优化

进度页继续保持“轻量学习档案”的定位，但增强专业度和布局稳定性。

#### 5.4.1 头部信息

保留：

- 完成章节数
- 平均得分

调整方向：

- 降低亮蓝区域对视线的抢夺
- 让数据卡风格更统一
- 让正文和数值层级更清楚

#### 5.4.2 章节列表

每个章节条目会改成更稳定的两段式结构：

- 第一行：标题摘要区 + 状态标签区
- 第二行：最近学习时间、得分等补充信息
- 第三行：继续学习 / 回顾这一章入口

目标是保证：

- 小屏阅读顺畅
- 标签不变形
- 数据信息不凌乱

### 5.5 第一章内容扩充

#### 5.5.1 当前问题

第一章已经解释了 Python 是编程语言、编程是在给电脑写规则，也提到了自动化、后端、数据分析和人工智能，但这些内容仍然偏“列名词”，缺少零基础用户可以代入的具体场景。

结果是用户知道“Python 很常见”，但仍然不容易回答“我学它以后到底能干什么”。

#### 5.5.2 扩充方向

增加一组更贴近日常和实际工作的说明，重点回答下面几个问题：

- Python 能解决哪些重复性问题
- Python 在工作场景里常见在哪里
- 为什么它既适合入门，又能继续往更复杂方向延伸

#### 5.5.3 新增内容重点

第一章将补充更具体的应用说明，例如：

- 批量整理文件和文件夹
- 自动处理重复性的表格工作
- 编写网站和服务端逻辑
- 做数据清洗、统计和图表
- 作为很多 AI 工具和自动化流程中的常用语言

这些内容不会停留在“它很强大”的表述，而是会解释：

- 这种使用场景具体在做什么
- 初学者为什么能理解它
- 以后继续学时会如何自然衔接到更深入方向

#### 5.5.4 配套练习与复习

为了让新增内容不只是阅读扩写，第一章还会同步补强：

- `sections` 中加入更具体的应用说明块
- `practiceTasks` 中加入场景判断或口头解释练习
- `reviewChecklist` 中加入“我知道 Python 常见用途”的检查项
- `quiz` 中补一题与应用场景相关的问题

## 6. 受影响文件范围

预期会修改以下文件：

- `frontend/src/style.css`
- `frontend/src/shared/ui/badge/PillBadge.vue`
- `frontend/src/app/pages/HomePage.vue`
- `frontend/src/app/pages/ProgressPage.vue`
- `frontend/src/app/pages/home-page.model.ts`
- `backend/content/chapters/python-overview.json`

如果实现过程中发现首页学习路线需要复用现有章节卡片能力，可能会顺带调整相关课程卡片组件，但不会扩大成整站重构。

## 7. 实现边界

- 不改变课程页和章节页已有基础路由结构
- 不改变后端接口形状
- 不新增复杂状态管理
- 首页学习路线的导航行为基于已有章节和进度数据判断，不引入新的权限层

## 8. 错误处理与边界情况

### 8.1 首页卡片解锁判断

若进度信息缺失，则沿用当前课程顺序的默认开放逻辑，至少保证首章可进入，避免首页入口全部失效。

### 8.2 进度页状态显示

若某章没有学习记录：

- 仍需稳定显示默认状态
- 不允许因缺少时间或得分字段导致布局错位

### 8.3 第一章内容兼容性

新增内容必须继续满足现有后端 schema 和前端渲染结构，避免为了扩写第一章引入新的内容类型或破坏现有章节数据格式。

## 9. 验证策略

实现完成后至少验证：

- 首页学习路线中，已解锁章节整卡可点击，未解锁章节不可进入
- 进度页中 `进行中` 标签在窄布局下保持单行
- 全局配色从高饱和蓝收敛为低饱和灰蓝体系
- 第一章新增了明确的“Python 可以做什么”内容与配套练习/测验
- 后端测试通过
- 前端测试通过
- 前端生产构建通过

## 10. 成功标准

本轮工作完成后，应达到以下结果：

- 用户不再明显感受到“蓝底黑字”的不专业观感
- 首页学习路线成为真正有效的入口，而不是只能看不能点的展示区
- 进度页状态标签在小屏和窄空间下保持稳定
- 第一章对 Python 的用途说明更具体、更有代入感，能增强初学者的学习动机
- 所有变更继续保持当前课程产品的整体一致性，而不是出现局部修补感
